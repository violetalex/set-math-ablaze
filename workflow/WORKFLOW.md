# 数学问题求解 + Lean 4 机器验证：工作流

目标：让"我证明了 X"这句话，在每一个环节都被独立检查一次；到最后，
读者能分清**哪一条被机器验证过、哪一条只是人类论证、哪一条是条件性的、哪一条还开着**。

本流程针对研究和推导型数学（分析、PDE、不等式、渐近），不是针对工程规约。
判据是两条：**反例可搜、陈述可形式化**。做不到这两点的命题，在台账里必须标
`CONJECTURE` 或 `INFORMAL-ONLY`。

---

## 0. 十条铁律（来自实际踩坑）

1. **先找反例，再写证明。** 一个漂亮证明在反例面前一文不值；反例在形式化之前找到，能省下几天。
2. **命题分状态，不许混着说。** 只有四种合法状态：`PROVED-INFORMAL`、`PROVED`（机器验证）、
   `CONDITIONAL`（必须列出假设）、`OPEN`。`REFUTED` 保留在台账里，附反例。
3. **条件定理永远不许被叙述成无条件定理。** 摘要、引言、结论三处的措辞必须与台账一致；
   终检时逐句对照（第 9 阶段）。
4. **循环论证要当作头号嫌疑人。** 最常见的失效是：引理 A 用引理 B，而 B 的证明里等价地
   用了 A 的结论（例：`bounded G₁ ⇔ c∂_ζG₀=0`）。
   对策：依赖必须是显式 DAG，审计员专门有一个 lens 查环路与等价替换。
5. **量词与极限顺序**单独设一个审计 lens。`∀ε ∃δ ∀x` 和 `∃δ ∀ε ∀x`、`lim sup` 与 `lim`、
   `先取 sup 再取极限` 与反过来，是分析类证明的第一大错误源。
6. **引用必须可检索。** 每条参考文献要有 DOI / arXiv 号 / zbMATH，且由第二个 agent 独立复核；
   查不到就删，不许"印象里有一篇"。
7. **不信任工具输出。** 转换、编译、脚本都可能静默丢东西（真实教训：pandoc 把公式编号丢了，
   且不报错）。凡是脚本产出的东西，都要有**独立于该脚本的交叉核对**（比如用 `.aux` 校验编号）。
8. **形式化要防"证了另一个命题"。** Lean 证明通过 ≠ 陈述对了。必须有陈述保真审计：
   假设逐条对照、量词逐条对照、边界情形（空集、零值、退化参数）逐条对照。
9. **sorry 与公理要独立审计。** 不靠 `lake build` 成功判断，靠独立的 `Audit.lean` +
   `#print axioms`；允许公理白名单：`propext`、`Classical.choice`、`Quot.sound`。
   自定义 `axiom` 必须登记在台账里，并标注它在论文中的对应物。
10. **形式化的范围要提前裁。** 整篇论文全部形式化通常不现实；诚实的做法是形式化"骨架 + 关键引理"，
    把依赖 Mathlib 尚不存在的分析工具的部分显式列为 `INFORMAL-ONLY`，并写进论文的说明。

## 1. 阶段总览

| 阶段 | 产物 | 通过条件（门禁） |
|---|---|---|
| P0 陈述锁定 | `docs/SPEC.md` | 对象、假设、结论、可伪性条件齐全；每条假设都能指出"去掉它会怎样" |
| P1 文献核实 | `docs/CITATIONS.md` | 每条引用有标识符 + 独立复核记录 |
| P2 证明构造 | `docs/LEMMAS.md` + 依赖 DAG | 每条引理有陈述、证明、依赖、状态 |
| P3 反例搜索 | `docs/COUNTEREXAMPLES.md` | 每个引理至少被一个 lens 攻击过；无未解释的数值违例 |
| P4 对抗审计 | `docs/AUDIT.md` | 每条 finding 有 CONFIRMED / PLAUSIBLE / REFUTED 判定 |
| P5 形式化映射 | `docs/FORMALIZATION.md` | 每条引理映射到 Lean 陈述或标 INFORMAL-ONLY |
| P6 Lean 实现 | `Lean/` 编译通过 | `mathlean check` 六道门全绿（见第 6 节） |
| P7 陈述保真 | `docs/FIDELITY.md` | Lean 陈述与 SPEC 逐条一致；假设不强于原文 |
| P8 成文与台账 | `docs/CLAIMS.md` + 论文 | 论文每一句断言都能追到台账一行 |
| P9 终检 | `docs/FINAL.md` | 下面第 9 节清单全部打勾 |

依赖关系：P0 → P1（可并行）→ P2 ⇄ P3 ⇄ P4（循环，直到两轮无新发现）→ P5 → P6 ⇄ P7 → P8 → P9。

## 2. P0 陈述锁定

写 `docs/SPEC.md`，必须包含：

- **对象**：定义台账（Definition registry）。每个符号一行：符号 / 一句话定义 / 定义域 / 正则性要求。
  例：`Δ_μ := ∂_ρ² − ρ⁻¹∂_ρ + ∂_ζ²`，作用在 `C²((0,∞)×ℝ)`。
- **假设**：逐条编号 `H1, H2, …`，每条注明"能弱化到什么程度"。
- **结论**：一句话，量词写全。
- **可伪性**：什么样的具体对象会推翻它？给出至少三个候选检验族。
- **反例边界**：已知的、结论不成立但接近的例子（这些将来要写进论文的 Remark）。

门禁：如果写不出"可伪性"三条，说明命题本身模糊，退回重写。

**只锁定原问题。** 把问题推广成更一般的结构（更一般的域/环、最优常数、n 元类比、
可变系数）不叫"严谨"，叫换题。推广只能写进「范围外」一节，不得进入假设或结论——
实测过一次：一道 $2ab\le a^2+b^2$ 被 P0 扩成"一般线性有序交换环"，下游 4 路攻击
全部去打有序环的零因子，真正的问题一个 agent 都没碰。

## 3. P1 文献核实

- 搜索用多路并行：arXiv、zbMATH/Google Scholar、期刊页。
- **每条条目必须带标识符**（DOI / arXiv / ISSN+卷期页）。
- 第二个 agent 独立打开标识符确认"标题、作者、年份、结论"四者一致；
  任何一项对不上就降级为"未核实"，不得进入正文。
- 记录被否掉的条目及原因（避免下一轮又把它捡回来）。

---

## 4. P2 证明构造 + P3 反例搜索 + P4 对抗审计

这三个阶段是循环，不是流水线。

### P2 证明构造
- 至少两条独立路线（不同分解方式），由不同 agent 写，再合并。
- 输出必须拆成**引理 DAG**：节点 = 引理（陈述 + 证明 + 依赖），边 = 依赖。
- 每条引理带 `status`：`PROVED-INFORMAL` / `CONDITIONAL` / `OPEN`。

### P3 反例搜索
并行攻击，每路一个 lens：
1. **数值/符号**：对恒等式做随机取值与符号计算；不等式扫参数。
2. **退化情形**：零、空集、常值、一维、轴对称、周期化、紧支撑。
3. **极限情形**：`t → -∞`、`ρ → 0`、`R → ∞`、`ν → 0`、`ε → 0`，分别取与联合取。
4. **量纲/尺度**：伸缩变换下两端是否同阶（标度不变的量最容易藏错）。

发现违例时的处理顺序：先怀疑引理陈述，再怀疑证明，最后才怀疑原始问题。

### P4 对抗审计
每个 finding 由 3 个不同 lens 的审计员独立判定，多数否决则丢弃；
每个引理至少被"逐行审计"一次（照着写，不看结论）。

判定用语固定：`CONFIRMED`（能复现的具体错误）、`PLAUSIBLE`（有具体疑点但未坐实）、
`REFUTED`（审计员自己错了）。**只允许 CONFIRMED 触发修改**；PLAUSIBLE 记入待办。

循环终止：连续两轮没有任何 CONFIRMED 新发现。

**预算**：攻击阶段是全流程最贵的一段（每条意见三个裁判）。`attack_budget` 限制该阶段
最多用几个 agent（默认 24），`max_findings` 限制每轮最多判几条（默认 6，按 fatal → major →
minor 排序）。超预算时停止并在返回值里报 `attack_skipped`——**不许安静截断**。
`minor` 意见只派一个审计员：用三个 agent 去核实一个措辞问题不划算。

## 5. P5 形式化映射

对每条引理回答三个问题：

1. Mathlib 里有没有现成的？给出名字（`#check` 验证过）。
2. 需要哪些**新定义**？新定义进入 Definition registry，并单独审计（定义写错比证明写错更难发现）。
3. 形式化成本：`easy`（<30 行）/ `medium` / `hard`（需要新引理库）/ `not-feasible`。

`not-feasible` 的引理标 `INFORMAL-ONLY`，并写清缺什么（例：需要 Mathlib 中尚缺的
二阶椭圆正则性）。这些必须在论文里明确说明，不能假装形式化过。

优先级：**先形式化结论依赖最多的引理**（骨架），再补叶子。

## 6. P6 Lean 实现

- 目录约定沿用现有工程：库名 `Foo`，源码在 `Foo/`，`Foo.lean` 汇总 `import`。
- 依赖顺序推进：每次只加一条引理，加完立刻 `mathlean check`。
- **成功判据必须结构化。** agent 的返回值是 `{status: OK|FAIL, detail}`，不许用
  "返回文本是否以 OK 开头"来判——实测有 agent 如实写了"声明已存在、编译通过、验证如下"，
  被判成 FAIL，连带 11 条下游引理全部阻塞。
- **依赖死锁要点名。** 当没有一条引理的就绪条件成立时，列出每条被谁卡住然后停止；
  "随便挑三条再试一遍"只会空转（实测 139 个 agent 里大半是这么来的）。
- **待办表按 id 摘除，不要按对象引用。** 跨 `agent()` 边界后引用不一定还相等：
  实测一轮里 118 次调用反复派发已经成功的 4 条引理，而 `done` 里明明记着它们——
  其余 10 条一次都没轮到。按 id 摘除与对象是否被复制无关。
- **禁止 `sorry`。** 写不下去就把该引理退回 P2，而不是留个洞。
- 独立 `Audit.lean`：对每条主要定理 `#print axioms`，比对白名单。
- `mathlean check`（工程里是 `scripts/check.sh`）是唯一验收口径，六道门：

| 门 | 检查什么 |
|---|---|
| `build` | `lake build` 通过 |
| `sorry` | 源码无 `sorry`/`admit`（注释与字符串不算） |
| `axioms` | `Audit.lean` 跑通；每个声明依赖的公理 ⊆ 白名单；自定义 `axiom` 已登记 |
| `statement` | 声明类型 ≡ `Statements.lean` 里独立重写的 `Challenge.<名字>` |
| `ledger` | 台账 ↔ 源码 ↔ 审计 ↔ 依赖图一致；**依赖不成环** |
| `docs` | 阶段产物齐全（`--strict-docs`） |

前三道门管「证得对不对」，`statement` 门管「证的是不是这句话」，`ledger` 门管
「说的和写的是不是同一件事」。

**kernel 重放不是门，是另一条验证路径。** `mathlean replay` 用 `leanchecker` 读编译产物、
不经 elaborator 再验一遍。`build` 走的是 elaborator（宏、tactic、`addDecl` 都在这条路上），
replay 只走 kernel；两者都过才算"证得对"。它对 `addDecl` / `kexactB` 这类绕过 elaborator
的构造是唯一有效的检查。局限：`leanchecker` 与工程共用同一个 kernel 实现。

**审计面不是门，是报告。** `mathlean frontier` 从台账的 `PROVED` 行出发，沿项目内部
声明做传递闭包，收集它们直接从 Mathlib/Init 借来的常量，按「公理 / 数学定理 /
策略支撑 / 定义与实例 / 语言基础」分类。它不改退出码——因为一个工程借用 500 条
Mathlib 引理并不算错——但它把「该核对什么」变成一份可数的清单。
证明规模越大，这份清单越重要：中段交给 kernel，两端（陈述与输入）留给人。
`ledger` 门里最值钱的两条：`PROVED` 声明必须在 `Audit.lean` 里被 `#print axioms` 过；
依赖图出现环就直接失败——那通常等于在用结论证结论（铁律 4）。

```sh
mathlean check --json        # 机器可读，便于 CI
mathlean check --no-build    # 只跑静态检查，秒级
mathlean status              # 阶段产物、台账计数、运行记录
mathlean doctor              # 环境体检，每个失败给修法
```

## 7. P7 陈述保真审计

由一个**没参与形式化**的 agent 做，逐条比对 `docs/SPEC.md` 与 Lean 源码：

- 假设：Lean 的假设集合必须**不强于**原文（多了就是证弱了，少了就是证了更强的命题——都要报）。
- 量词：逐条标出 `∀/∃` 的顺序。
- 定义：Lean 用到的每个定义与 registry 逐字核对（`Δ_μ` 的系数、`Γ` 的定义都要核）。
- 边界：空集、零、退化参数在 Lean 里是否被静默排除（`[Nonempty]`、`≠ 0`、`Fin (n+1)` 之类）。

产出 `docs/FIDELITY.md`，每条给 `MATCH` / `WEAKER` / `STRONGER` / `DIFFERENT`。
出现 `DIFFERENT` 一律回炉。

---

## 8. P8 成文与台账

`docs/CLAIMS.md` 是唯一真相，格式见 `templates/CLAIMS.md`。规则：

- 论文中每一个定理、命题、引理、Remark 断言，都必须有一行台账。
- `PROVED` 行的 `lean` 列必须是真实存在的声明名，且出现在 `Audit.lean` 里。
- `CONDITIONAL` 行必须写清条件，正文中该定理的标题/摘要措辞必须带条件。
- `OPEN` 与 `REFUTED` 也要写进去——审稿人最看重的往往正是"你知道自己没证出来什么"。

摘要与引言按台账生成，不允许自由发挥。

## 9. P9 终检清单

- [ ] `mathlean check` 全绿；`Audit.lean` 输出无 `sorryAx`，公理 ⊆ 白名单
- [ ] 台账每一行状态合法；`PROVED` 行全部能在 Lean 源码里定位到声明
- [ ] 依赖图无环（`mathlean check` 的 `ledger` 门会报）
- [ ] `docs/FIDELITY.md` 无 `DIFFERENT`
- [ ] 引用全部带标识符，且有独立复核记录
- [ ] 摘要/引言/结论中，每个"我们证明了"都能追到 `PROVED` 行
- [ ] 条件性结论在正文三处（摘要、定理陈述、结论）措辞一致
- [ ] `INFORMAL-ONLY` 的部分在论文里被明确说明
- [ ] 所有反例（`REFUTED` 行）在论文中作为 Remark 出现，而不是被悄悄删掉

## 10. 规模与时间

- 一条引理的完整循环（构造 → 反例 → 审计 → 形式化）通常 1–3 天；形式化 `hard` 的往往是瓶颈。
- 判断"值不值得形式化"：该引理是否 (a) 被结论直接依赖、(b) 陈述短、(c) 不依赖尚未形式化的分析工具。
  三条都满足才做。
- 保留每一轮的审计记录；**撤回的命题比证出来的命题更有信息量**。

## 11. 工具与记录

### 11.1 分工

- **确定性的部分**（脚手架、编译、扫描、审计、台账）由 `mathlean` 实现，有单元测试和自检；
- **需要判断的部分**（证明、反例、审计、形式化、保真）由 `workflow.js` 编排 agent 完成，
  产物一律落到 `docs/` 和 Lean 源码，用门禁回验。

agent 之间不直接传状态，只通过文件交接——这样每一步都可审查、可 diff、可重放。

### 11.2 工程自带检查器

`mathlean new` 会把检查器复制进工程的 `tools/`。工程因此不依赖 `~/math-lean` 是否存在，
检查结果也可复现。升级是显式的：

```sh
mathlean upgrade --root <工程>
```

### 11.3 检查器自己也要被检查

一个没人验证过的门禁只是装饰。`mathlean selfcheck` 造一个临时工程，然后**故意弄坏**
每一种情形，看门是否按预期亮红灯：

```
✔ 干净工程                    全部通过
✔ 真写了 sorry                 按预期被 sorry 拦下
✔ sorry 只出现在注释里           全部通过
✔ PROVED 的声明不存在            按预期被 ledger 拦下
✔ PROVED 没有公理审计            按预期被 ledger 拦下
✔ CONDITIONAL 没写假设          按预期被 ledger 拦下
✔ REFUTED 没给反例              按预期被 ledger 拦下
✔ 非法状态                     按预期被 ledger 拦下
✔ 依赖成环                     按预期被 ledger 拦下
✔ 未登记的自定义公理              按预期被 axioms 拦下
✔ 登记过的自定义公理放行           全部通过
```

改检查器时必须同时改 `tests/` 和 `selfcheck.py`，两边都绿才算没改坏。

### 11.4 运行记录

每跑一次完整流程，`workflow.js` 会在 `docs/RUNS/` 留一份 JSON：时间、问题陈述、
每阶段产物、确认的审计问题、被降级/撤回的引理。目的是**换人接手时不用问"上次做到哪"**。

### 11.5 配置

`mathlean.ini`：

```ini
[project]
lib = MyProblem

[lean]
mathlib = .lake/packages/mathlib
audit = Audit.lean

[check]
build = true
timeout = 1800
strict-docs = false

[axioms]
allowed = propext, Classical.choice, Quot.sound
; 自定义公理：登记名 = 论文中对应物
```

删掉也能跑（用默认值），但 `lib` 最好显式写上。
